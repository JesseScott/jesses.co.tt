# jesses.co.tt

Jesse Scott's personal site, a small static site hosted on WHC (LiteSpeed shared hosting). The GitHub repo is **public**.

## Build and deploy
- Source is `src/`, built to `dist/` by `build.mjs` (zero dependencies, Node 20+). Run `npm run build`. Never edit `dist/` (it is gitignored).
- Pushing to `master` runs `.github/workflows/deploy.yml`: build, then upload `dist/` to WHC over FTPS (only changed files). PRs run `build.yml`.
- **Merging to `master` publishes to the live site.** Work on a branch, open a PR, and merge only when asked to publish.
- Verify live changes with `curl` against `https://www.jesses.co.tt/...`, or open the page in the browser pane.

## How pages work
- An `.html` file in `src/` that starts with a `---` front matter block is rendered into the shared layout (`src/_partials/`). Keys: `title`, `description` (required, the build warns if missing), `nav` (`about` | `projects` | `contact` | `none`), `bodyAttrs`. The file body is only the page content.
- Files without front matter are copied as-is. That includes the privacy policies (`privacy*.html`), `blog.html` and `header.html` (legacy).
- Project pages live in `src/_projects/`. A new project also needs an entry in `src/projects.html` (the `all` group, plus `mobile` or `software` as fits; keep rough alphabetical order). Image convention: `<div class="portrait"><div class="media"><img ...></div></div>`, with real `alt` text.
- `sitemap.xml`, canonical tags and Open Graph tags are generated by the build. Canonical host is `https://www.jesses.co.tt`; `src/.htaccess` redirects http and the bare domain to it.

## Conventions
- Colours `#5F6B74` (text) and `#52703F` (links) were darkened on purpose for WCAG AA contrast. Do not lighten them.
- Optimise media before adding it: images through `sharp`, video as `.mp4` (H.264, `+faststart`), never large GIFs.
- The Play Store listings link to the Meanwhile and Moonlight privacy policies. Keep those URLs stable, including `privacy-meanwhile.html#contact`.
- Some files use CRLF line endings. Prefer small, targeted edits.

## Writing project pages
- Content comes from the Obsidian vault (`C:\Vaults\randomized-rituals\Creative\`, see the user-level CLAUDE.md) and from the project's live GitHub repo. Check both; the repos are usually more current than the vault.
- State only what the source supports. Do not put words in Jesse's mouth or invent features, dates or store availability. Check whether an app is actually on Google Play before saying so.
- Use only what is fit for a public page. Leave out private working notes, submission logs, unpublished fiction, console links and licensing worries.
- Do not publish a project that has not been announced. Drafts for projects not ready yet are kept on a **local-only branch that must not be pushed**, because this repo is public.
